新五题质量初审

本次只评题目设计与验收可行性，不要求启动 Android。五题均以 RecreationBench 项目为选题来源，但大量规则是明确的合成扩展，不是原版应用行为的完整复刻。以下难度是设计判断，尚无模型成功率支持。

题目 核心交互链 初审判断 主要不足
RB-001 Trekarta 航点校勘 导入同名不同ID航点 → 编辑/筛选 → 跨页查看 → 重启 → 导出 中等，身份与持久化一致性有价值 地图空间交互弱，实际更接近带GPX输入的记录管理；不应借原仓库体量声称高难
RB-002 Shader 实验台 双文档编辑 → 异步编译 → 错误保留上次有效画面 → 撤销/切换 → 保存恢复 → PNG导出 中高，五题中优先保留 真实GPU及异步竞态仍未验证；CPU公式参考图不能替代Android渲染验收，手势难度低
RB-003 图片转PDF 同名图导入 → 排序/旋转/移除撤销 → 保存草稿 → 源文件消失后恢复 → 导出并保留历史 中高，五题中优先保留 72dpi内容检查不能证明原图清晰度；拖动和文件选择器交互尚未回放
RB-004 openScale 测量记录 双用户导入 → 单位换算编辑 → 统计/图表联动 → 删除撤销 → 重启恢复 中等，计算边界清楚 仍偏CRUD与数值一致性，异步复杂度为零；现有C=4缺少足够区分度，不建议据此排在Shader之上
RB-005 指示器授权恢复 修改配置 → 进入系统授权页 → 返回刷新 → 撤销授权 → 重连/进程恢复 中等的Android专项题 授权状态机范围窄，不含真实隐私事件；X=4不等于整题高难，纯预览产品使用无障碍服务的动机偏人为

评分依据与局限

依据《复杂交互任务定义.pdf》的C状态耦合、H链深、A异步、L生命周期、G手势、X跨边界六维分别判断。知识树用于检查覆盖范围，不作为加分条数。维度分数是作者初评，不能简单求和当成实测难度。

真正增加难度的是前一操作改变后一操作的正确结果，例如Shader过期编译结果覆盖新文档、PDF草稿变更错误修改历史文件、单位切换导致重量反复舍入。仅多几个页面、字段或独立操作不算复杂交互。

当前五题普遍重状态与文件结果、轻真实移动手势和视觉还原。它们适合评价功能实现与一致性，暂不足以作为五道高难移动端前端复刻题。建议优先深化Shader/PDF，航点和测量保留为中档，授权题作为专项覆盖题。

已修正的审核问题

  • 授权题原先把所有“从设置返回未操作”都写为DISABLED，与已有授权应保持可用的情况冲突；已改为查询系统真实状态。
  • PDF题允许页面尺寸误差0.5pt，但原检查对渲染像素数严格相等，可能误拒合法输出；已修正并补边界测试。
  • PDF原图清晰度未被72dpi检查证明，现明确保留为未验证项。

当前证据能说明什么

公开题面有固定输入、身份规则、操作分支、恢复边界和输出协议；各题具有离线oracle及负向测试。它们能检查部分数据/文件结果，不能证明Android控件可操作、GPU行为、系统授权回调、界面质量或模型实际解题难度。Golden实现和完整Android验收均尚未完成。

离线测试：33 项通过（4+4+9+8+8），不代表 Android 验收。
