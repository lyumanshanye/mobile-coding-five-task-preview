# 多媒体笔记的组织、回收与恢复

状态：构题草稿，未冻结。参考 GitHub Omni Notes，实现完整 Android 离线笔记 App。

用户把项目资料整理成文本和清单笔记，附上图片或文件，使用分类与标签检索。归档、回收、恢复、合并和备份后，笔记身份、清单状态与附件都必须保持可用。与文件编辑器题不同，本题重点是笔记对象及其附件、组织关系的生命周期。

| ID | 业务要求 | 判定关注点 |
| --- | --- | --- |
| NT-01 | 新建和编辑文本笔记，保存标题和正文，支持同名笔记 | 修改按对象身份定位，同名标题不导致覆盖；取消语义待核验 |
| NT-02 | 创建清单，添加/编辑/删除条目、完成与撤销完成 | 条目身份和顺序保持，重开后完成状态正确；相同条目文本不混淆 |
| NT-03 | 使用系统入口添加图片、音频或通用文件附件，并打开或移除 | 内容和类型正确，附件不是占位图；从备份恢复后仍可打开 |
| NT-04 | 分类和标签组织，多维检索、改名及批量归类 | 列表筛选与详情关系一致，改变组织方式不丢内容或附件 |
| NT-05 | 按文本检索并打开具体笔记；编辑后重新检索 | 同标题不同内容可定位，搜索作用域含哪些归档/回收状态须冻结 |
| NT-06 | 归档、移入回收站、恢复和永久删除 | 明确区分可逆和不可逆操作；恢复后清单状态与附件一致；默认列表按状态过滤 |
| NT-07 | 多选笔记并执行批量操作或合并 | 未选中对象不改变；合并后的正文顺序、组织关系和附件规则需原版核验后公开 |
| NT-08 | 导出备份，增加或修改数据后恢复 | 笔记、清单状态、分类标签和附件共同恢复；覆盖/合并/重复规则需冻结 |
| NT-09 | 生命周期与系统共享 | 保存后force-stop、重开及共享入口得到正确内容；公开契约不依赖内部数据库模式 |
| NT-10 | 长正文、多附件、多选、键盘与返回交互，旋转和字体放大 | 选择状态不误作用于其他笔记，正文和附件可访问，布局不遮挡关键操作 |

正式夹具将包含同名笔记、重复清单条目、不同类型附件及可识别内容。验收需要打开附件并验证内容、执行完整状态转换，不能仅检查缩略图数量或备份文件存在。

云同步不是当前范围：参考仓库把同步列为未来开发，不能把它当作已有参考能力。完整设计截图、合并和恢复策略尚缺，因此这份草稿还不是可独立作答题。

`input/design/checklist-detail.png`提供已经实际核验的清单详情状态，第一项已完成，其余两项未完成。此局部设计与设备证据不替代同名对象、附件、分类标签、多选、合并及备份恢复的完整范围。

`input/lifecycle-contract.md`明确已归档清单经回收站恢复后仍保持归档状态，以及条目和对象身份的保留要求。其他未冻结规则仍须补齐后才能正式交付。

`input/media/`提供同一组原创测量数据的PNG与CSV。附件测试应使用可辨认内容，验证文件归属、完整内容及图片实际打开效果，不得仅按名称和图标数量评分。系统选择器中的筛选标签与目录可能同名，应按正确角色定位。
