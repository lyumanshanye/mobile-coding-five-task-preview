# 离线多账户账本

状态：构题草稿，未冻结。参考 GitHub Money Manager Ex；尚不能正式交给模型作答。

实现完整可运行的 Android 离线账本 App。用户需要管理银行与现金账户，记录收支、账户间转账和交易更正，在交易列表、账户余额及汇总页面得到一致结果。参考页面截图和操作任务书冻结后提供；提交完整工程和可安装 APK。

核心难点是同一交易的生命周期如何影响多个页面。不能把转账记成收入，不能编辑后额外生成重复交易，也不能只改当前页数字而不更新另一账户和重启后的数据。

## 功能契约草稿

| ID | 要求 | 判定关注点 |
| --- | --- | --- |
| LG-01 | 使用系统文件入口新建/打开本地账本；权限取消可返回，不能静默覆盖已有账本 | 文件选择、App 返回、重开及取消后的数据状态。原版文件格式兼容要求待冻结 |
| LG-02 | 创建账户，指定名称、类型、币种、初始余额和开户日期 | 交易归属稳定；不允许早于开户日期的交易；账户显示与余额一致 |
| LG-03 | 新增收入与支出，填写金额、日期、收付款方、分类、备注和编号 | 金额按精确小数处理；列表、详情、余额、收支汇总同时反映新记录 |
| LG-04 | 同币种账户间转账，同时更新转出/转入账户 | 总资产不因转账改变，转账不计入收入/支出；更改转账金额后双方均重新计算 |
| LG-05 | 更正已有交易的金额、日期和分类，取消编辑 | 更正保留交易身份，不新增重复项；取消不改变任何相关账户及汇总 |
| LG-06 | 保留作废交易的记录并按原版规则处理余额与筛选；支持对账状态 | 作废、未对账、已对账不能混同。具体金额和统计口径待设备核验后冻结 |
| LG-07 | 按账户、日期、类型或分类查看交易及汇总 | 边界日期明确；筛选不修改底层账本；转账在收入/支出统计中排除 |
| LG-08 | 创建并选择收付款方和分类，改名不破坏既有交易关联 | 新建后能立即使用；改名/删除约束以原版实测语义为准，不臆造级联规则 |
| LG-09 | 保存、更换页面、终止进程后重开，以及备份恢复 | 交易和关联账户一致，不重复入账；备份格式及恢复覆盖策略待冻结 |
| LG-10 | 长列表、软键盘、返回、旋转、深色和字体放大保持关键流程可操作 | 输入不串到账户/交易；已保存结果稳定；视觉与语义证据均需采集 |

本题先限定同币种账户，避免把汇率政策未定义的问题混入账本一致性。云同步、投资行情、第三方支付和付费 API 不在当前草稿范围。完整 App 应包含导航和上述业务闭环，不能以单个静态表单替代。

金额、账户名、交易日期、记录顺序和记录数量会变化。示例数据不是唯一测试数据，不得针对固定编号、备注或截图写死结果。对实现内部类名、数据库表名和 resource-id 不作要求。

## 可理解的例子

活跃交易的金额、身份、取消编辑、日期与筛选口径详见 `input/ledger-contract.md`。该文件包含逐步余额表和剩余待冻结项，与本题面一起阅读。

银行初始1000.00、现金初始100.00；银行入账200.00、支出37.45，再转账80.00到现金。应得到银行1082.55、现金180.00、总额1262.55，收入200.00、支出37.45。把该转账改为60.00后，银行1102.55、现金160.00，总额仍1262.55。随后把原支出改为45.10，银行1094.90、现金160.00、总额1254.90。

以上是草稿中待原版设备核验的业务期望，不是已执行结果。正式题面还需冻结图稿、交易状态口径、平台环境及恢复策略。
