# 操作链草稿

以下完整操作链尚未完成验收。每日数值习惯的一条历史更正、重启与导出已完成局部验证，不代表全部参考解通过。

1. 创建每日二值、每周三次和数值习惯，加入两个同名计划；分别录入不同数据。
2. 在跨月的历史窗口录入完成、未完成、0和跳过，再回首页及详情比较日期和值。
3. 修改较早的一天，逐页查看后续连续记录、周期完成度和强度重算；导出并对照历史。
4. 对同一数值分别使用至少/至多目标，检查边界值、撤销及取消编辑。
5. 排序、归档、恢复、改名后重新定位同名计划，确保记录身份不串换。
6. 保存、force-stop、重开、备份恢复，再核对历史、统计与用户导出。

日历必须实际点击目标日期，图表必须实际交互；不得通过直接改数据库代替操作。准备历史夹具可以用公开导入入口，但需记录原始文件、解析规则和导入结果。隐藏测试改变日期范围与数值，仍遵守公开算法。

## 已明确的每日数值子链

从原始history.json状态出发，打开Coffee并在日历定位2026-10-15，确认原值4.00与对应备注。修改为1.00并保存，返回历史/统计页，再终止并重启App，检查记录、备注及导出。强度按input/daily-numeric-contract.md重算，修改之前日期不应变化。其他习惯及日期的原始记录全部保持不变，同日不能新增重复记录。

该子链覆盖实际日历输入、历史重算、持久化及导出一致性。它不替代前面的重名习惯、周期计划、归档恢复、目标编辑及布局健壮性操作，也不代表这些要求可以删除。
