# 可回溯的习惯计划与统计

状态：构题草稿，已有局部设备验证，尚未冻结或完成整题验收。参考 GitHub Loop Habit Tracker，实现完整可安装的 Android 离线习惯管理 App，而非只记录今日是否完成的清单。

用户同时维护每日阅读、每周三次训练以及每日数值目标。补录历史、撤销误记或改变历史数值后，首页、日历、连续记录、统计和导出结果必须基于同一份历史数据。不同习惯可以重名，不能用显示标题当唯一标识。

| ID | 业务要求 | 需验证的后果 |
| --- | --- | --- |
| HB-01 | 创建二值与数值习惯，指定名称、提示、单位、目标和周期 | 每日与非每日计划可区分；编辑某条计划不覆盖同名计划 |
| HB-02 | 在首页记录、撤销当日结果，在历史日历补录或修正过去日期 | 首页与详情一致；多次编辑同一日期不生成重复事件 |
| HB-03 | 区分未记录、实际0、跳过与完成；数值目标支持至少/至多方向 | 未记录与显式0必须保留不同原始状态；每日数值强度计算中缺失日按0参与，见daily-numeric-contract.md。方向切换的完整交互仍待核验 |
| HB-04 | 支持如每周三次的周期计划 | 每七天三次的自动休息及平滑强度规则见weekly-binary-contract.md；原始记录与派生状态分离，不得把每天未勾选都视为违约 |
| HB-05 | 历史修改后重算统计、连续记录和习惯强度 | 改变远期历史也影响后续结果，不只刷新当前单元格。每日数值及每七天三次二值强度的具体公式见两个公开契约；连续记录等其余规则仍待冻结 |
| HB-06 | 在日期范围内查看历史和图表，处理跨月、跨年和当天边界 | 日期身份按冻结时区一致，不能因页面切换或重启偏移一天 |
| HB-07 | 编辑目标/周期、归档及恢复习惯 | 历史记录保留；每日数值目标变更追溯重算历史强度，见daily-numeric-contract.md；周期改变及归档恢复规则仍待核验 |
| HB-08 | 筛选、排序与多选管理 | 排序后编辑仍作用于正确习惯，归档项不混进默认活动列表 |
| HB-09 | 导出用户可读取历史，备份并恢复 | 导出的日期、值、跳过/缺省、备注与界面一致；恢复后的历史和统计一致。格式与覆盖策略待冻结 |
| HB-10 | 保存后重启、旋转及放大字体，保持日历和图表可操作 | 真实输入、日期定位与状态稳定，不能以不可交互截图替代图表/日历 |

任务复杂度来自时间序列及派生状态的一致性。`input/history.json`及`input/README.md`已提供跨月、同名习惯、缺省/零/跳过的初始历史与组合操作。具体统计算法、参考图、候选App初始化接入和导出格式仍未冻结，因此当前草稿不可作为可独立作答题。

不依赖在线账户或后端。系统提醒和桌面组件是否纳入最终题目，须先验证参考环境与平台行为，本草稿不以未验证能力补足难度。

每日数值习惯的部分契约已补充于`input/daily-numeric-contract.md`，明确原始状态、强度递推、历史更正及每日数值目标变更。它不替代尚未冻结的每周计划、连续记录、目标方向切换和周期变更规则。

`input/design/coffee-calendar-initial.png`补充原始历史下的日历展开态；日期单元格须可操作，修改应作用于真实记录并更新关联视图。它与首页设计共同提供局部参考，仍不构成完整设计稿。

`input/weekly-binary-contract.md`补充Training每七天三次计划的原始/自动休息状态区分、区间生成及14天平滑强度规则。它不等于自然周清零，也不替代连续记录、月计划或周期变更的完整规格。

`input/design/training-*.png`提供周计划初始详情、日历、日期状态选择框、修改后日历与重启后详情，对应操作卡HB-W01及HB-W05至W07。这些截图与规则共同描述真实状态转换；修改后数值应来自历史重算，不能硬编码37%/34%或10/9。
