# 播客：订阅、下载队列与离线续播

## 用户目标
为一次通勤准备三集播客：订阅本地测试RSS，调整播放顺序，下载后离线播放，并在后台、重启及下载失败后恢复。

在Android端实现以下可交互工作流。参考应用是设计与功能来源，不要求复刻全部应用。

## 输入与初始状态
input/mock_server.py启动确定性HTTP服务，默认8765。RSS和3个60秒WAV均在input/server，音频为本题生成测试音。模拟器连接10.0.2.2；真机用adb reverse tcp:8765 tcp:8765后连接127.0.0.1。每次重启服务重置第3集首次503；无需公网。

## 需求

### R1
订阅RSS后显示节目与3个单集；订阅页、首页、单集页共享订阅状态，重复刷新不重复插入同一guid。

来源：reference_documented；对应图：S01, S03, S04, S06。

### R2
将第1、2、3集加入队列，调整为2、1、3；播放第2集时列表、底栏和播放器一致，移除未播放第1集不重置当前进度。删除正在播放的单集须先确认；取消不改变队列与进度，确认后暂停并移除，下一集等待用户主动播放。

来源：synthetic_extension；对应图：S02, S05。

### R3
支持下载、失败反馈和重试；本题服务使第3集首次返回503，重试成功后离线可播放，不能把半文件标为完成。

来源：synthetic_extension；对应图：S04, S05。

### R4
已下载第2集播放至12秒暂停，后台返回与重启后仍从12秒附近继续；拖动至30秒并切换1.5倍速，时间轴和暂停状态正确。进度容差1秒。

来源：synthetic_extension；对应图：S02。

### R5
拒绝通知权限不妨碍前台播放；播放中进入后台可继续，用户主动暂停后不得自动重播。

来源：synthetic_extension；对应图：S02。
